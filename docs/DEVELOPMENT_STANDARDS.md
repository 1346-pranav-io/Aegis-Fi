# Development Standards

Status: DRAFT · Version 0.1. Applies to all code and docs. Violations block merge.

## 1. Typed interfaces
- Python: type hints everywhere; `mypy --strict` on `common, domain, store, evidence, runtime, llm, capabilities, services`; no untyped public functions in any package.
- Cross-module interfaces are `Protocol`s or Pydantic models in `domain/` — not dicts.
- TypeScript: `strict: true`; API types generated from OpenAPI.

## 2. Schema validation
- Pydantic v2 models for: API DTOs, domain objects, agent tasks/results, tool arguments/results, LLM structured outputs, config, JSONB columns (each with `schema_version`).
- Validate at the boundary (ingress and egress); forbid extra fields (`extra="forbid"`) unless explicitly justified.
- LLM output = untrusted input: parse → validate → bounded repair → fail typed.

## 3. Modular architecture
- Module layout and allowed dependencies per SYSTEM_ARCHITECTURE.md §2; enforced by import-linter contracts in CI.
- Capabilities do not import each other. `runtime/` composes.
- No cyclic imports; no business logic in `api/` or LangGraph graph definitions.
- Adding a module/agent/service requires a `decisions.md` entry.

## 4. Immutability and provenance
- Never write code that UPDATEs or DELETEs `source.*`, `evidence.*`, `audit.*`, `report`, `agent_step`.
- Corrections are new rows with `supersedes`.
- Every derived artefact records: producer name+version, inputs (ids+hashes), `as_of`, config hash.
- Content hash = SHA-256 of canonical JSON (sorted keys, normalised numbers/timestamps) — single shared implementation in `common.hashing`.

## 5. Error handling
- Typed exceptions in `common.errors` (`ValidationError`, `PermissionDenied`, `NotFound`, `ConflictError`, `ExternalServiceError`, `BudgetExceeded`, `IntegrityError`).
- No bare `except`/`except Exception` except at process boundaries, where the error is logged with context and converted to a typed result.
- Capabilities return `AgentResult(status=…)` for expected failures; raise only for programmer errors.
- External calls: timeout + bounded retry + backoff + jitter; idempotency keys for writes.
- Never swallow errors to "keep the run going" without recording a failed step.

## 6. Logging and observability
- structlog JSON; required context: `correlation_id`, and where applicable `case_id`, `run_id`, `step_id`, `agent`.
- Never log secrets, raw PII, full prompts with unpseudonymised data, or full LLM responses at INFO.
- Log events are named (`event="evidence.created"`) not sentences; levels used consistently.
- Audit events (append-only table) are separate from logs.

## 7. Security practices
- Least-privilege DB roles; parameterised queries only; no LLM-generated SQL.
- Secrets from environment/secret store; `.env` files git-ignored; secret scanning in CI.
- All LLM calls via `llm/`; prompt text treats retrieved content as untrusted data.
- Dependency lockfile; dependency review for each addition.

## 8. LLM and agent rules
- Deterministic first. LLM only where AGENT_SPECIFICATIONS says so.
- Prompts are versioned files (id, version, hash); change ⇒ version bump ⇒ replay fixtures regenerated.
- Model IDs in config only. Temperature and sampling params in config and recorded.
- No agent self-assessed numeric confidence treated as probability.
- Record/replay for all tests and experiments.

## 9. ML and experiment rules
- Features built by pure functions with `as_of`; no label access in feature code.
- Every training run logs to MLflow: params, metrics, dataset manifest hash, code commit, seed, environment digest.
- Model artefacts versioned and registered (`ml.model_artefact`); loading an unregistered artefact is an error.
- Temporal splits generated by code from config.
- Metrics in docs/papers must trace to a stored run id. No hand-typed numbers.
- Calibration reported before any output is called a probability.

## 10. Data rules
- Public/synthetic data only in the repo; large datasets fetched by scripts with checksums, not committed.
- Labels stored apart from features (`source.label`).
- Dataset adapters are versioned; ingestion idempotent.

## 11. Human approval
- Gated actions (D-09) must call `services.approvals.require(action, subject)`; direct state changes bypassing it fail review.
- Agents may only create `PendingApproval`.

## 12. Code style and review
- ruff (lint + format) and mypy clean; line length per ruff config.
- Small PR-sized changes; each includes tests and doc updates.
- Naming: modules `snake_case`, domain terms as in glossary (`claim`, `evidence`, `score`).
- Review checklist: invariants (CLAUDE.md), boundaries, tests, logging, errors, docs, `decisions.md` entry if architectural.
- Security-reviewer pass required at phase exit and on changes to auth, DB roles, gateways.

## 13. Versioning
- Semantic version for the package; separate versions for: rule packs, prompts, capabilities, schemas, model artefacts, report templates, datasets. Each stored with the outputs they produce.
- Migrations forward-only with tested upgrade path.

## 14. Git and CI (when a repository exists — owner to confirm remote, Q-08/Phase 1)
- Trunk-based with short-lived branches; conventional commit messages.
- CI stages: lint → type → unit → import-linter → integration (Postgres) → schema/OpenAPI snapshot → security scan.
- No direct pushes of unreviewed architecture changes.

## 15. Documentation
- Every requirement ID referenced by at least one test (traceability table maintained by documentation-engineer).
- Docs updated in the same change as behaviour.
